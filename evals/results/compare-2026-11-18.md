## What the transcripts show

- **Unity's one failure (`point_light`) is a silent property failure.** The
  agent created `lamp` with `component_properties: {"Light": {"type": "Point"}}`;
  the tool answered success but left the light Directional, and the agent then
  read `type: 1` as Point (it is Directional). Wish Engine checks every value it
  writes and answers an error when one cannot be applied.
- **One tool error in every Unity task:** `ManageScene Load` wants a folder as
  `Path` and the scene name apart; the agent first passed the file path each
  time.
- The checks differ: Unity's falling box is a static check of the saved scene
  (rigidbody with gravity, solid colliders), Wish Engine's simulates 150 ticks.

## The first Unity run was invalid (a harness bug, fixed)

The runner copied each task's scene into `Assets/Scenes` while the editor ran
in the background. The editor did not import them, so the agent could not
open the scene (4/8, every failed scene byte-for-byte the start scene; the
transcript of `delete` shows "Scene file not found"). Fix: `run.py
prepare-unity` writes all task scenes before the editor opens, the run checks
that each is an untouched copy, and transcripts are kept in
`<COMPARE_WORK>/transcripts/`. The numbers above are from the corrected run.

## Limits

Eight simple scene tasks: no game code or game systems. One run per engine.
The tasks were written for this comparison by the Wish Engine side (M7), in
neutral words, but the home advantage is not zero.
