# Release 1.1, package 1: project kinds and the kind-first New project

Status: built on branch `project-kinds` (21 November 2026). Plan:
[1.1-2d-and-online.md](1.1-2d-and-online.md) §5 and §6 (package 1).

## 1. Problem

Release 1.1 brings a 2D kit. The user asked that opening a project separate 2D
and 3D projects with their own templates, as Unity's hub does. Today every
project is the same kind of thing: the welcome screen offers one flat list of
templates, an empty project is always a 3D one (camera, ground, sun), and the
editor cannot tell a platformer from an arena. The later 2D packages (sprite
sheets, tilemaps, the editor's 2D mode) need one place that answers "what kind
of project is this?".

## 2. Options

1. **A key in `wish.json`** (`kind`), optional. A project without it is 3D.
2. A separate project file or folder layout per kind. Rejected: it splits the
   format, and a 2D project can still hold 3D and the other way round.
3. Infer the kind from the scene (an orthographic camera means 2D). Rejected:
   it is a guess, it changes while editing, and it cannot say what a new scene
   should start with.

## 3. Decision

- `wish.json` gets an optional `kind`: `"2d"` or `"3d"` (ADR-028 rule 5:
  formats change by addition). `ProjectConfig.kind` is an `Option`; it is
  written only when set, so every 1.0 project stays byte-identical, also after
  the engine rewrites `wish.json` for another reason (default scene, packages,
  `wen migrate`). `ProjectConfig::kind()` is the one function that answers the
  question: the project's kind, `3d` without the key. The editor reads it
  through `project_info` (`project.kind`) into one field; the later 2D mode
  uses the same.
- A word that is not a kind is an `invalid_project_file` error at `/kind` with
  a hint (the valid words, and that leaving the key out means 3D); `check`
  reports it through the project file's usual path.
- **Only a new project writes the key.** `create_project` (a 3D project) and
  `create_project_of_kind` write it; `create_from_template` writes the
  template's kind (a template without the key is 3D). The engine's
  examples are the templates: `bricks` says `2d`, the others stay as they are
  (3D). There is no new template folder: "Empty 2D" and "Empty 3D" are not
  folders but what `create_project_of_kind` makes, shown as the last tile of
  each kind, as the empty project was before.
- `Template.kind` comes from the template's `wish.json`, so templates that
  packages bring are sorted by kind the same way.
- `wen new <folder> --kind 2d|3d [--template <id>]`. Without a template, the
  kind picks the empty project; with one, the template's kind is used, and a
  `--kind` of the other kind is an error (`template_kind_mismatch`, the hint
  names the templates of the asked kind). A word that is not a kind is
  `invalid_parameter` with a hint. The JSON answer carries `kind`.
- **The welcome screen:** the steps are now 1 Who helps you, 2 What kind of
  game (two large cards, 3D and 2D, 3D chosen first), 3 Start from (the
  templates of that kind, the showcase first, the empty project last), 4 Name
  and place. Choosing the other kind selects the first template of that kind.
  The Hub's "Start from it" on a template also sets the kind.
- **The kind sets defaults, never limits** (plan §5): in a 2D project the
  editor's Create menu lists sprites and particles first and lights last, a
  camera made from it is orthographic, and *New scene* starts with an
  orthographic camera and nothing else (`scaffold::starting_entities(kind)`,
  one table for `wen new` and the editor). A 2D project's starter game code
  turns around Z, and its agent guide (`CLAUDE.md`) says it is 2D. Not built
  here: the editor's 2D mode, sprite sheets, tilemaps, 2D physics (packages
  3 to 8).

## 4. Test plan

- `wish_control/tests/project_kinds.rs`: a project without `kind` is 3D and its
  `wish.json` is byte-identical, also through a workspace; a kind round trips;
  a bad kind is an error with a hint, and `check` reports it at `/kind`; a new
  project says its kind (3D by default, 2D with a flat scene that passes
  `check`); templates have a kind and a new project takes it.
- `wish_cli/tests/project.rs`: `wen new --kind 2d`, the template's own kind, a
  mismatch writes nothing, a word that is not a kind.
- `wish_editor/tests/welcome.rs`: the welcome screen's kind-first flow, found
  by widget names (3D templates, then 2D templates, an empty 2D project and
  Bricks make 2D projects that pass `check`).
- `wish_editor/tests/menus.rs`: a 2D project's Create menu order, a camera
  made by hand, a new scene.
- `wish_editor/tests/languages.rs`: the new interface texts are in all 11
  languages (the step titles, the two kind cards and their lines, the two
  empty-project tiles).
- Both user guides describe the new flow (the link test checks them).
