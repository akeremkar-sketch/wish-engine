# M3 — First pixel: design note

Status: written (15 November 2026). Read before writing code. Context: [ROADMAP](../ROADMAP.md) M3, [DECISIONS](../DECISIONS.md) ADR-012/013, [ARCHITECTURE](../ARCHITECTURE.md) "Render pipeline".

## 1. Goal and limits

At the end of M3: a scene file (M2) is drawn to a PNG **without opening a window**; models come from glTF; the question "which entity is at this pixel" is answered from the id buffer; shader errors arrive in the shared diagnostic format with file and line. The window comes last, and thin.

**Out of scope (not done in M3, goes on the M11 list):** animation/skeleton (M6), clustered lights (one directional light is enough; point/spot lights come in M6), IBL/environment map (M3 has a procedural sky + constant ambient light), MSAA, post-processing (except tone mapping), bindless/GPU-driven drawing. These are inside the "baseline" (ADR-012) but belong to later milestones; the render graph (§4) makes it possible to add them later.

**Invariants:** 2 (determinism): rendering is **outside** the determinism boundary (ADR, architecture §Frame loop) — simulation state is never read back from the GPU, and render does not write to the ECS. 8 (observability): every render feature can be seen with `wen capture`/the id query and is tested headless. 5 (diagnostic): a shader error is also a `Diagnostic`.

## 2. Crates and dependency direction

| Crate | Responsibility | External dependencies |
|---|---|---|
| `wish_import` | glTF/GLB → CPU data (`Model`: meshes, materials, textures, node tree). Knows nothing about the GPU | `gltf`, `image` |
| `wish_transform` | `Transform` (local), `GlobalTransform` (derived), propagation system along the hierarchy | — |
| `wish_render` | wgpu device, resources, render graph, PBR, shadow, sky, tone mapping, debug views, capture, scene extraction from the ECS | `wgpu`, `naga`, `pollster`, `bytemuck`, `png` |
| `wish_window` | `winit` window, presentation surface, simple fly camera (last work package) | `winit` |

Direction: `wish_render` → `wish_import` (data types), `wish_transform`, `wish_ecs`, `wish_asset` (asset path resolution); `wish_window` → `wish_render`. `wish_import` and `wish_transform` do not know render. wgpu lives only in `wish_render` (invariant 6: an external library is used only through its own wrapper). `wen` (CLI) is a temporary host; when the control plane `wish_control` arrives in M4, `capture`/`describe_view` move there, and the function stays in the `wish_render` API (invariant 4: control plane first — until M4 the `wish_render` functions are the single entry point, and the CLI only calls them).

## 3. Components (schema first)

All are `#[component]`, with doc comments and units:

- `Transform { translation: Vec3 (m), rotation: Quat, scale: Vec3 }` — in the scene file `translation`/`rotation`/`scale`; for `rotation` the extra `euler_deg` short form is **not in M3** (the example in the architecture document was for illustration; the exact form is the quaternion). If needed, it is asked in M4 as an editor/agent convenience.
- `GlobalTransform` — cannot be written (the engine derives it, like `Hierarchy`). **Decision:** instead of adding a new managed-component registration to `wish_ecs` in WP2 (the crate with unsafe), the M2 `SceneId` path is followed: writing it in a scene is rejected with `managed_component`.
- `Camera { fov_y_deg (1–179), near (m), far (m) }` — `aspect` comes from the capture size. A scene can have several cameras; capture picks one with `--camera <scene_id>` (otherwise the first camera).
- `DirectionalLight { color: Color, illuminance_lux, shadows: bool }` — the direction is the −Z axis of the entity's `GlobalTransform`.
- `Model { asset: AssetRef }` — unfolds the scene of a glTF/GLB under this entity. **Decision (relation to the M2 prefab):** glTF nodes do **not** become scene entities; `Model` is a single entity and the node tree inside it is kept on the render side (it is drawn only with its own transform). Reason: writing hundreds of nodes of one model into the scene file is pointless and bloats hash/undo; if manual editing is needed, "unpacking" into a prefab is considered in M8a. The id buffer works at entity level (Model = one entity); the child node id comes to `describe_view` as an extra field (`node`).
- `MeshRenderer { mesh: AssetRef, material: AssetRef }` — **not in** M3: for primitive shapes (cube, sphere, plane) a `Primitive { shape: enum, size... }` + `Material` (base color, metal, roughness) component is needed to build tests and pre-showcase scenes without glTF. → The `Primitive` and `Material` components are in M3; the `.mat.json` file, the part of ADR-013 for custom shaders, comes later.
- Resources: `Sky { zenith: Color, horizon: Color, ground: Color, sun_disk: bool }`, `Ambient { color: Color, intensity }`, `Exposure { ev100 }`.

## 4. Render architecture

```
ECS world ─(extraction, read-only)→ RenderScene (CPU: cameras, lights, draw list, id map)
RenderScene + Model/Texture cache ─→ Renderer (wgpu)
   passes (render graph nodes): Shadow → Opaque PBR → Sky → Tone mapping → [Debug: Id | Depth | Normal | Wireframe] → Present | Capture
```

- **Extraction (`extract`)** reads the ECS read-only and produces a `RenderScene`: visible draws `(model/primitive, world matrix, material, entity id)`. The order is fixed by scene id (so debug outputs are repeatable). The render side does **not** write to the ECS.
- **Render graph:** node = pass (input/output texture declaration), edges are resource use. In M3 the graph is small and linear, but the node interface (`Pass { reads, writes, run }`) exists from the start so that shadow/post/side-output passes can be added later (ADR-012). Side outputs run only when requested.
- **Targets:** main color `Rgba16Float` (HDR) → tone mapping (Khronos PBR Neutral; not ACES: no desaturation side effect, suitable for comparison with glTF samples) → `Rgba8UnormSrgb`. Id `R32Uint`, depth `Depth32Float`, normal `Rgba16Float` (or octahedral `Rg16Float` — measured in WP6).
- **PBR:** glTF 2.0 metal-roughness model (base color, metal-roughness, normal, occlusion, emissive; `KHR_materials_emissive_strength` and `KHR_texture_transform` are supported in M3; other extensions are skipped with an `unsupported_extension` **warning**, not silently ignored). Light: one directional light + constant ambient + a procedural sky reflection approximation.
- **Shadow:** a single shadow map for the directional light, an orthographic section fitted to the scene bounds (2048², PCF 3×3, slope-scaled bias). **Cascaded** shadows (CSM) are in the ADR-012 baseline, but the need for a large open world is measured in the M7 showcase game; in M3 the interface is ready for a cascade count, and the implementation has 1 cascade.
- **Wireframe:** the `POLYGON_MODE_LINE` feature is not on every adapter (especially software); so `LineList` is used with an edge index buffer derived from the mesh. It works everywhere.
- **Debug views** (`lit | ids | depth | normals | wireframe`): each is a separate output; `ids` and `depth` can also be read numerically (`describe`).

## 5. Shader language and errors (ADR-013 check)

ADR-013 says "WESL maturity is checked at the start of M3". Status: the `wesl` crate is 0.6 (compiler), `naga` 30 is a WGSL parser + validator. **To be checked in WP1:** (a) `import` resolution and error locations with `wesl`, (b) `naga` error ranges (spans) → line/column. Decision rule: if the WESL compiler gives errors with locations and the dependency tree fits the license list, use WESL; if not, use **our own simple `#import "path"` preprocessor** (in M3 there are 4–6 modules, the preprocessor is ~100 lines; the source map keeps a line mapping) + naga. In both cases the error is a `Diagnostic`: `shader_syntax`/`shader_validation`, with file + line + column + a quote of the source line + hint. Shader files are embedded in `crates/wish_render/shaders/*.wgsl` (`include_str!`) and can also be hot-reloaded from files during development (WP7). User shaders (`*.mat.json`) are out of M3 scope.

## 6. Headless render and CI

- **Adapter choice:** `Renderer::new(RenderOptions { backend, software: bool })`. `software: true` → `force_fallback_adapter` (Windows: DX12 over WARP; Linux: lavapipe/Vulkan — `mesa-vulkan-drivers` is installed in CI; there is no macOS CI in M3). If there is no real GPU and no software adapter, there is a **clear diagnostic** (`no_gpu_adapter`, hint: software adapter/`--software`), no crash.
- **Golden image:** PNG; the comparison is `max channel difference ≤ T` and `different pixel ratio ≤ P` (start with T=2/255 software–software, P=0.5%; in WP1 the lavapipe ↔ WARP difference is **measured** and the thresholds are set from it). If needed, goldens are kept separately per platform (`golden/windows`, `golden/linux`). Deviation report: a diff image + a numeric summary; it is refreshed with `UPDATE_GOLDEN=1`, and the diff is reviewed (like M1's `TRYBUILD=overwrite` routine).
- **Risk — software rendering is not identical across drivers.** Mitigation: threshold + deterministic scene (no randomness), single sampling, known simple scenes. This risk is the **exit condition** of WP1: if the same scene does not come out the same within the threshold on two platforms, the M3 plan is revised (the user is informed).

## 7. Import (`wish_import`)

GLB/glTF with the `gltf` crate: mesh (position, normal, tangent, UV0, index; if there is no tangent, mikktspace-like generation — in WP4 the license of what the `gltf` crate provides or of a separate small library is checked), material, texture (PNG/JPEG decoding with `image`; no KTX2 in M3), node tree; no unit/coordinate conversion is needed (ADR-021: same as glTF). Errors are `Diagnostic`s (`gltf_parse`, `unsupported_extension`, `missing_buffer`, `image_decode`) with the file path and (if possible) the JSON pointer. `*.meta.json` `import` settings: `scale`, `generate_tangents`, `flip_uv_y` — only these in WP4 (the M2 meta infrastructure is used, an unknown key is `unknown_key`).

Asset path resolution uses `AssetRef` (M2): `Model.asset = "assets/models/crate.glb"`; a file that does not exist gives `asset_not_found` in `wen check`.

## 8. Command line (temporary host; moves to `wish_control` in M4)

| Command | What it does |
|---|---|
| `wen capture --example E --scene S [--root R] [--camera ID] [--size 1280x720] [--view lit\|ids\|depth\|normals\|wireframe] [--software] --out file.png [--json]` | Loads the scene, draws it, writes a PNG; with `--json` it gives `{ok, path, size, adapter, hash}` (hash: of the PNG bytes; depends on the GPU, **not** a determinism claim) |
| `wen describe --example E --scene S [--camera ID] [--at x,y] [--json]` | From the id buffer: with `--at`, the entity at that pixel (scene id, node); otherwise the screen box, visibility percentage and distance to the camera of every visible entity (the core of `describe_view`) |
| `wen view --example E --scene S` | Opens a window (WP8) |

## 11. Risks

1. **Software render difference** (§6) — WP1 exit condition.
2. **Dependency weight:** the `wgpu` tree is wide (build time, license variety). WP1 measures it with `cargo-deny`; if a license outside the allow list appears, it stops and reports (adding a new license is a user decision).
3. **Build time/CI time:** `wgpu` adds minutes to the first build; the CI cache (`Swatinem/rust-cache`) is added in WP1.
4. **Scope growth:** CSM, IBL and point lights are tempting; M3 is "first pixel", and these are written on the list (§1).

## 12. Decisions / approvals that belong to the user

- **Downloading the glTF sample models** (Khronos glTF-Sample-Assets, several licenses: mostly CC-BY/CC0/SI; they will be downloaded only for local testing without entering the repo, and will **not be added** to the repo): approval will be asked at the end of WP4, stating the source, file names and size.
- If a new external dependency has a license outside the allow list: approval to add it to the license list.
- Scope: everything this note calls "not in M3" (animation, IBL, CSM, point light, KTX2) is **inside the 1.0 scope** and is written into later milestones; if a change grows the scope, it is stated here.

## 14. Implementation notes

### WP1 — proof work (spike)

- **Result: the §6 risk did not happen at this stage; the plan continues unchanged.** A triangle with colored corners (an edge-coverage + color-interpolation test), 256×256, `Rgba8UnormSrgb`: between WARP on Windows ("Microsoft Basic Render Driver", DX12) and lavapipe (Vulkan) on Linux CI the **largest channel difference is 1/255**, with a one-level rounding in 5.3% of pixels; no difference at edge pixels. Threshold: a pixel is "different" if its channel difference exceeds 2, and at most 0.5% of pixels may differ. When light/texture/shadow arrive (WP3–WP5) the same measurement is repeated (`measure_the_difference_between_two_captures`, a manually run test).
- **Golden images** are `crates/wish_render/tests/golden/*.png` (produced from WARP), refreshed with `UPDATE_GOLDEN=1`. Each run leaves what it drew as `target/tmp/captures/<name>-<operating system>-<backend>.png`; CI stores these as **artifacts** (to compare the two platforms and to examine a failed golden test).
- **CI:** `mesa-vulkan-drivers` (lavapipe) is installed on Linux; WARP comes with the system on Windows. CI now runs on milestone branches too (`m[0-9]*`). The Windows job takes ~6 min with the `wgpu` build.
- **Error handling:** the default behavior of `wgpu` on an uncaught error is to panic; `Gpu` sets up its own logger handler and runs every GPU job under a validation + memory error scope (`gpu_error`). If there is no adapter, `no_gpu_adapter` (separate hints for software/hardware); if the device cannot be opened, `gpu_device_failed`; if readback fails, `gpu_readback_failed`; an invalid size gives `invalid_capture_size`.
- **Shader diagnostics:** `check_wgsl` (`naga` 30): syntax `shader_syntax`, validation `shader_validation`; the location is a character column (tested with a comment containing Turkish characters), and the source line is added to the message. On a validation error `naga` gives several spans; the narrowest one is chosen. Known limit: `naga` ties some type errors not to the `return` line but to where the value of the wrong type is defined (the test documents this).
- **ADR-013 decision:** WESL 0.6 was tried; for details and the decision see [DECISIONS](../DECISIONS.md) ADR-013 "M3 check". In short: in M3 `naga` + a small import preprocessor with a source map (WP3), and WESL later behind the interface.
- **Dependencies:** `wgpu` 30, `naga` 30, `png` 0.18, `pollster` 1, `bytemuck` 1. The licenses passed `cargo-deny` in CI (no need to add to the allow list).

### WP2 — transforms, scene components, extraction

- **`wish_transform`:** `Transform { translation (m, alias "position"), rotation (unit quaternion [x,y,z,w]), scale (default 1) }` and the derived `GlobalTransform { matrix }`. `update_global_transforms(&mut World)`: the parent first, roots in entity order, children in sibling order; `GlobalTransform` is written only if the value changed (so change tracking stays meaningful, and a second run does not change the world hash). An entity without `Transform` does not move its children (it counts as the identity transform) and does not carry `GlobalTransform`; if an entity loses its `Transform`, its old `GlobalTransform` is deleted. A zero or non-finite rotation counts as "no rotation", and NaN does not propagate into the hierarchy.
- **Decision — `GlobalTransform` is not managed, it is a component that cannot be written in a scene file.** The same path as `SceneId`: the `ENGINE_WRITTEN` list of `wish_scene` (for now `SceneId`, `GlobalTransform`) rejects these names with the `managed_component` code and a hint, and removes them from the candidate list; `wish_ecs` was not touched.
- **Components (`wish_render::components`), all with schema, units, ranges:** `Camera { fov_y_deg 1–179 (60), near (0.1 m), far (1000 m) }`, `DirectionalLight { color, illuminance_lux 0–200000 (100000), shadows (true) }`, `Primitive { shape: Cube | Sphere | Plane }` (size comes from the `Transform` scale: cube 1 m, sphere diameter 1 m, plane 1×1 m in XZ facing +Y), `Material { base_color, metallic 0–1, roughness 0–1 (0.5), emissive }`, `Model { asset: AssetRef }`; resources `Sky { zenith, horizon, ground }`, `Ambient { color, intensity }`, `Exposure { ev100 (14) }`. Colors are linear RGB. **Deviation from the design note:** `Primitive` has no size field (the scale already exists; one-place rule).
- **Extraction (`wish_render::extract`):** `extract(&mut World) -> RenderScene` reads the world read-only: cameras (view matrix, position, fov in radians, near/far, `projection(aspect)` for wgpu with Z 0–1 / Y up), directional lights (direction = the entity's −Z axis, radiance = color × lux), draws (entity, world matrix, primitive or model path, material; an empty `Model` path is not drawn), sky, ambient (multiplied by intensity), exposure. All in entity order; the same world gives the same scene. `far <= near` or a non-finite placement gives `invalid_camera`. Extraction does not change the world hash (tested).
- **A `camera` module was opened in `wish_core::math`** (`glam` 0.34 moved the projection constructors under `camera::rh::proj::directx`; `perspective_rh` no longer exists).
- **`wen` now knows the engine types:** `wish_cli::types` (`register_scene_types`: engine types + the types of the selected example). `wen check/fmt/run --scene/mv` validate scenes that contain cameras/lights/primitives; `wen schema` lists the engine types. The scene-only component of the `stress` example, `Model`, became `MeshRef` (name clash).
- **Tests:** `wish_transform` (8): parent-child, rotation+scale, an intermediate entity without rotation, only the changed is written, reparenting/removal, broken rotation, schema defaults + alias hint, same hierarchy same hash. `wish_render/tests/extract.rs` (6): scene file → world → extraction (camera, light direction, draw order, material, placement of a child relative to its parent, resources), read-only + repeatable, empty world, empty model, broken camera, 6 component value errors (with location). `wen` end-to-end test (+1): render scene `check` (zero diagnostics) + `run --scene` + errors with location + schema.

### WP3 — render core and `wen capture`

- **Shader library (implementation of the ADR-013 decision):** `ShaderLibrary` keeps modules by name; `#import name` lines import (each module once, after the modules it imports; a cycle is `shader_import_cycle`, a missing module is `shader_import_unknown` with "did you mean", a broken line is `shader_import_syntax`; all at the file/line/column of the import line). For every line of the merged source the original file + line is kept; a `naga` error is mapped with this map back to **the module where the error is** (tested: an error on line 4 of `brdf.wgsl` is reported as `brdf.wgsl:4` when `opaque` is merged). Engine modules: `common` (frame data), `sky`, `brdf`, `tonemap` and three passes (`sky_pass`, `opaque`, `tonemap_pass`).
- **Frame:** three passes, fixed order: sky (full-screen triangle, HDR `Rgba16Float`) → opaque (glTF metal-roughness BRDF: GGX distribution, height-correlated Smith visibility, Schlick Fresnel, Lambert diffuse; one directional light + ambient light + Karis's analytic environment BRDF approximation for the sky reflection; emissive; `Depth32Float`, back-face culling) → tone mapping (Khronos PBR Neutral) → `Rgba8UnormSrgb` capture. Values are **pre-exposed** (the sky and opaque pass write multiplied by the exposure); exposure is `1 / (1.2 · 2^EV100)`. For now only the first directional light is used (many lights M6). The render graph (passes with declared inputs/outputs) will come with the shadow and debug passes (WP5/WP6); the "graph interface from the start" in the design was postponed until then because it would have been an abstraction with no consumer.
- **Physical units made consistent (a change from WP2):** `Ambient.intensity` is now lux (default 20000, open shade), `Sky.luminance` was added (cd/m², default 20000), `Material.emissive` 1 = `EMISSIVE_NITS` (30000 cd/m², default as bright as a white surface in the sun). So with the default EV100 = 14 the sun, sky, ambient and emissive surfaces look natural on the same scale.
- **Primitive meshes:** cube (24 vertices), UV sphere (32×16), plane; deterministic generation on the CPU; a unit test checks that every triangle faces outward (winding agrees with the normal) and that normals are unit length. The vertex buffer is position + normal (`f32` little-endian bytes).
- **`Renderer`** builds the pipelines and primitive meshes once; `render(gpu, scene, camera, w, h) -> Frame { image, camera, drawn, warnings }`. Camera choice: the given entity (`not_a_camera`) or the first camera (`no_camera`). What cannot be drawn comes back as a **warning**, not hidden: `degenerate_transform` (zero/infinite scale), `model_not_drawn` (glTF in WP4).
- **`wen capture --example E --scene S [--root R] [--camera ID] [--size WxH] [--view lit] [--software] --out x.png [--json]`:** loads the scene, propagates the transforms, extracts, draws on the shared device, writes a PNG; the JSON output contains the camera scene id, draw count, adapter and warnings. `--camera` takes a scene id (`unknown_entity` + suggestion), `--view` was only `lit` in WP3; the other views came in WP6 (below). Example project: `examples/first-pixel`.
- **Measurement — hardware ↔ software:** the same scene at 1280×720 between an RTX 3060 Ti (Vulkan) and WARP (DX12) differs by **at most 1/255** (one level in 12% of pixels). In CI, between Linux lavapipe (Vulkan) and the WARP golden image the difference is also **at most 1/255** (one level in 16% of pixels). The three paths (hardware, WARP, lavapipe) give practically the same image; the golden image threshold is as in the test triangle: at most 0.5% of pixels with a channel difference above 2.
- **Finding 1 — when separate devices draw at the same time, the WARP process crashes** (`STATUS_ACCESS_VIOLATION`, inside the driver; repeatable in parallel tests; threads sharing one device are fine). **Fix:** one process-wide GPU lock (`gpu_lock`: device opening, every `checked` job, readback) and a per-process shared device `Gpu::shared`. Regression test: four threads, each with its own device, three frames each.
- **Finding 2 — the WARP device was lost only in the release build.** `wgpu` turns on the DX12 debug layer in a debug build; it is off in release. With the layer off, the reference Khronos PBR Neutral form (early `return` + division by `peak`) makes WARP lose the device, every later buffer becomes invalid, and `create_buffer_init` of `wgpu` **panicked** with `expect`. Narrowing down: passes were turned off one by one → tone mapping; shader variants → `tonemap_pbr_neutral`. **Fix:** the function was rewritten in an equivalent form with no branches and no division by zero (the golden image did not change). **Extra measures:** `create_buffer_init` is not used at all (buffers are filled through the queue; an error becomes a diagnostic instead of a panic); `checked` reports the root cause in the order memory → internal → validation (`gpu_out_of_memory`, `gpu_error`); the device-lost callback is recorded and every later job tells the real cause with `gpu_lost`; the `WGPU_DEBUG`/`WGPU_VALIDATION` environment variables are honored; **CI runs the render tests in release too.**
- **Tests:** `wish_render/tests/render.rs` (6): from a scene file to the pixel (sky blue, the lit face of the cube red, the lamp emits green light, the gold sphere a warm reflection, the ground gray) + golden image; repeatability; camera choice/errors; warnings for what cannot be drawn; clean check of the engine shaders and an error mapped to its module; concurrent drawing with separate devices. Mesh unit tests (2). `wen capture` end to end (+1): PNG, JSON, five error cases.

### WP4 — glTF import and textured PBR

- **`wish_import` (CPU data only, knows nothing about the GPU):** `load_model_file(path, name)` (reads external `.bin`/images from the folder next to it) and `load_model_bytes`. `Model`: meshes (each with primitives; position, normal, UV0, tangent, index, material), glTF metal-roughness materials (base color, metal, roughness, emission, normal scale, occlusion strength, double-sided, alpha mode + cutoff), textures decoded to 8-bit RGBA, node tree. `placed()` gives every primitive in the tree with its world matrix (iterative, depth limited: `MAX_NODE_DEPTH` 256, a file with a cycle does not go on forever); `bounds()`.
- **Supported:** triangle list/strip/fan; `TEXCOORD_0`; base color, metal-roughness, normal, occlusion, emissive textures; `KHR_materials_emissive_strength`; if there is no normal, a **flat normal** (vertices are unwelded), if there is no tangent and there is a normal texture, it is **generated** (UV-derivative based, not MikkTSpace; same result with non-mirrored UVs). **Unsupported things are warnings, they do not drop silently:** `unsupported_extension` (an extension the file *uses* but we do not read), `unsupported_texcoord_set` (a UV1+ texture), `unsupported_primitive_mode` (point/line), `primitive_inconsistent`; an extension that is *required* and not supported (e.g. Draco) is an **error** (`unsupported_extension`, hint "re-export without the extension").
- **Errors (all with the file path, with hints):** `gltf_parse`, `gltf_invalid`, `gltf_file_missing` (if a separate `.bin` is missing: "use a single `.glb`"), `gltf_image` (must be PNG/JPEG), `gltf_texture_too_large` (2²⁸ pixel limit).
- **Finding — the `gltf-json` library panics on a hostile file:** the accessor index is used without a bounds check (`root.accessors[i]`, in the validation hook, before the index validation). **Measure:** the library call is inside `catch_unwind`; the panic becomes a `gltf_invalid` diagnostic (tested: a mesh that points to an accessor that does not exist). The panic message is still written to stderr.
- **Render (textured PBR):** the vertex format is 48 bytes (position, normal, UV, tangent); the shader samples five textures (a missing slot gets a 1×1 default: white, flat normal), normal map with TBN, occlusion darkens only indirect light, alpha MASK `discard`, a separate pipeline for double-sided materials and normal flipping on the back face. The **mip chain is on the CPU** (2×2 box filter) and there is **no anisotropy**: so that every adapter does the same sampling from the same data (golden image repeatability). `Renderer::upload_model(gpu, path, &Model)` and `has_model`; if a `Model` entity is not loaded, a `model_not_loaded` warning (with the file location). The model's own materials are used (the `Material` component is only for primitives). **Alpha BLEND** is drawn opaque and gives an `alpha_blend_not_blended` warning (blending M6).
- **`wen capture`:** loads the files of the scene's `Model` entities from the project; a model that cannot be loaded (broken, missing) **is not drawn, the rest is drawn, and a warning is given** (`model_not_loaded` + the import message/hint); the import warnings of the model are also passed on; duplicate warnings for the same file are shown once.
- **Deliberate limits:** no `KHR_texture_transform` and other extensions (a warning); `#sub_object` is ignored and the model is drawn whole; the meta file settings (`scale`, `generate_tangents`, `flip_uv_y`) are not in this package, they are added when the need is measured with the Khronos samples; no KTX2/Draco; skeleton/animation M6.
- **Tests:** `wish_import/tests/gltf.rs` (11, with GLBs produced in code): a complete quad + material; PNG textures (RGB/gray → RGBA) and material bindings + generated tangents; node tree placement + limits; flat normals; strip/fan; warnings for unsupported things; required extension error; `emissiveStrength`; 3 broken files (parse/invalid/image); external `.bin`; a tree with a cycle. `wish_render/tests/models.rs` (5, with the software adapter): texture colors left/right, only multipliers, alpha mask opens a hole / opaque does not, double-sided back face, normal map changes the lighting. Texture mip unit tests (2). `wen capture` loads a model, warns on a broken model (+1). The existing golden image **did not change**.

### WP5 — directional light shadow

- **A single shadow map, 2048², `Depth32Float`.** The light section (orthographic) is fitted to the bounding boxes of **everything** drawn in the scene (`fit_light`): the 8 corners of the local box of each draw are moved to the world and from there to light space; the x/y/z range is computed, and a 4-texel margin is added. So the map covers exactly the top of what is drawn; if the light direction is parallel to the up vector, a fallback axis is chosen. Unit test: for four light directions (down, slanted, up, −Z) all corners of two boxes are inside the map (x,y ∈ [−1,1], z ∈ [0,1]). If there is nothing to draw or the numbers are not finite, there is no shadow (a 1×1 map is cleared to 1.0).
- **Shadow pass:** depth only from the light view; back faces are not culled (so single-sided surfaces like a plane also cast shadows); slope-scaled depth bias (`constant 2, slope 2`). It shares the draw list and the draw uniforms (with dynamic offset) with the main pass: `draw.wgsl` is a shared module, `shadow_pass.wgsl` is new.
- **Sampling:** **3×3 PCF** in the opaque pass (`textureSampleCompareLevel`, valid also in non-uniform control flow), a comparison sampler with **nearest** filtering (so every adapter compares the same texels), a **normal offset** along the surface normal from the surface (1.5 texels) and a **depth bias** tied to the texel size (2 texels / depth range): without the surface shadowing itself (acne), and without the shadow detaching at the contact corner. Outside the map or `shadows: false` → lit (1.0). The shadow darkens only the **direct light**; ambient and sky reflection are not shadowed.
- **Frame data** grew to 336 bytes (light matrix + shadow parameters); the shadow map and the comparison sampler are in the frame bind group (`group(0)` binding 1, 2).
- **Deliberate limits:** surfaces with alpha MASK **do not cut holes** in the shadow (the shadow pass has no textures); single cascade (CSM later, the open-world need is measured in M7); the soft shadow penumbra is constant (3×3), not tied to the light size; in closed scenes (like a 30 m ground) the map is spread over the whole scene, so a texel is ~1.5 cm.
- **Tests:** `fit_light` unit tests (2); `wish_render/tests/render.rs`: `objects_cast_shadows_on_the_ground_and_a_light_can_turn_them_off` (at the tip of the orb's shadow the shadowed image is clearly darker, the shadowless one is lit; the shadows of three objects change the total image by hundreds of pixels; away from the shadows the two images are equal) and a scene without light. **Method note:** the shadow tests I first wrote measured the point right under the object; since that point stays behind the object in the image, the test was passing **for the wrong reason**. The new test, which compares (shadowed/shadowless) and measures from the shadow tip, caught this. The golden image was refreshed with shadows (reviewed visually); the difference between RTX and WARP is again ≤ 1/255.
- **Observation — a one-time `models` failure:** `wish_render/tests/models.rs::double_sided_materials_show_their_back` failed once on the first run of a freshly built release binary; it did not happen again in the next 33 runs (also with the D3D shader cache cleared). The cause could not be determined. The test uses the same shared device from several threads and its threshold may be on the edge (`c[0] > 2*c[1]` on a dim surface). If it is seen in CI, first make the threshold more robust (brighter color/light), then look for concurrency.

### WP6 — debug views and `wen describe`

- **Architecture:** `Renderer::collect` produces the draw list (it now gives every draw an **id** derived from its order in the scene = index + 1; in the `params2.w` field of the draw uniform); `render` and the new `render_view` use the same list, so a debug view sees **the same** geometry, transform and hiding as the real draw. The code is in `renderer/debug.rs` (pipelines, `View`, `IdBuffer`, `describe`) and `shaders/debug_pass.wgsl`; render still does not write to the ECS.
- **Views:** `ids` (`R32Uint` target; in the image every id gets a separate color with a golden-ratio hue, sky black), `depth` (distance to the camera, **logarithmic**: near is white, `far` is black; in scenes with a wide range both near and far are readable, but in the default 0.1–1000 m range the contrast between near objects is low), `normals` (world-space normal, `n·0.5+0.5`, flipped on the back face; sky dark gray), `wireframe` (dark fill + edges; the fill is pushed slightly back, so the edges behind are **hidden** and those in front are visible). All write to `Rgba8Unorm` (no sRGB conversion: the byte is the value the shader computed). `lit` is the normal `render` (byte-for-byte the same in the test).
- **Normal buffer question (§13.2) closed:** no separate normal/id buffer is kept; each debug view draws its own pass when asked. If a G-buffer is needed (M6 lighting), it will be measured then.
- **Wireframe edges:** `mesh::edge_indices` extracts the unique edge pairs from the triangles in a fixed order, computed once when the mesh is loaded (`GpuMesh.edges`). Since the faces of a cube do not share vertices, each face has its own 4 edges + a diagonal (6×5 = 30); the diagonals that split the surface in two are visible (deliberate: showing the triangulation is wanted).
- **`describe`:** from the id buffer, for every visible entity the pixel count, the **visible percentage on screen** (`visible_fraction`: visible pixels / the pixels the entity would cover if drawn *alone*; the part outside the image is not counted), the screen box (`[left, top, right, bottom]`), the distance to the camera (the center of the world-space bounding box); also entities that were drawn but gave no pixel at all (`hidden`: behind something else or outside the image). Measuring the percentage needs one extra render per entity (at most `MAX_VISIBILITY_MEASUREMENTS` = 128 entities; `None` for more). The order is scene order.
- **Command line:** `wen capture --view lit|ids|depth|normals|wireframe` (a wrong name: `unknown_view` + "did you mean"); `wen describe --example E --scene S [--root R] [--camera ID] [--size 640x360] [--software] [--json]` (JSON: `visible[{entity, pixels, visible_percent, bounding_box, distance}]`, `hidden[]`, adapter, warnings; `entity` is the scene id). The two share a common `prepare` step. In M4 `wish_control` wraps them.
- **Tests:** `wish_render/tests/debug_views.rs` (8): the id buffer finds four entities at the right pixels (sky/outside the image `None`); in the `ids` view 4 entities + black = 5 colors; `depth` lamp > orb > far ground; `normals` ground green, front of the sphere blue; `wireframe` edge pixel count is bounded, most pixels are dark; `describe` in a closed scene (a big cube in front, a small cube right behind it, a cube leaking from the edge, a cube outside the image) the visible/hidden list, the front cube 100% and 8.00 m, the leaking cube 50–97%, the pixel total is **equal** to the id buffer; a wrong camera/view name gives a hint; `lit` = `render`. Golden images: `view-ids`, `view-depth`, `view-normals` (reviewed by eye; wireframe line rasterization may depend on the adapter, so it is not a golden, it is a structural test). CLI: in `project.rs` `capture` draws every view, `describe` JSON and text output, error hints. `cargo test --release -p wish_render -p wish_cli` is green.
- **Method note:** my cube expectation (18) in the `edge_indices` unit test was wrong (30, since the faces of a cube do not share vertices); it was caught when the test ran.

### WP7 — shader diagnostics and hot reload in development

- **The diagnostics were ready in WP3** (`shader_syntax`/`shader_validation`, file + line + column + source line + hint, mapped to the module's own file when it comes with `#import`); WP7 connected them to the developer loop: `check_shaders(&library)` checks all pipeline shaders without a GPU (`ENTRY_SHADERS`), `engine_shaders_from_dir(dir)` puts `dir/<name>.wgsl` files in place of the built-in modules (the real file path shows in the diagnostics).
- **Hot reload:** `Renderer::with_shaders(gpu, &library)` and `Renderer::reload_shaders(&mut self, gpu, &library)`. The new pipelines are first built on the side; they are swapped only if all succeed, the **loaded models stay**; if there is an error, the renderer keeps drawing with the old shaders (the error comes back as a diagnostic with a location). The material bind groups of the models were created with the old layout; since wgpu treats layouts of the same structure as equal, they are compatible with the new pipelines (verified with a test: after reloading, a textured model is still drawn correctly).
- **Command line:** `wen shaders [--dir D] [--json]` (check without a GPU; the exit code is failure if there is a problem); `wen capture|describe --shaders D` draws with that folder (if it is broken, it returns `shader_syntax` without drawing). Watching files and refreshing automatically in the window was left to `wen view` of WP8 (the same `reload_shaders` will be called).
- **Tests:** `models.rs`: the sky shader is painted blue from a file, the model stays and is drawn; a broken file is rejected (file name, hint) and the image does not change. `project.rs`: `wen shaders` clean/broken, `capture --shaders` rejects a broken folder.
- **Observation (WP6 CI):** the test `watch_reloads_a_valid_change...` failed once on Linux: since the test saved with `fs::write` (it truncates first, then writes), the watcher also reported the empty file as "rejected". The test's write is now atomic (temp file + rename, like the save of an editor). A note for the product side (for the M4/M5 list): real editors can also truncate and write; `watch` may wait a short stability period before reporting an empty/half file.

### WP8 — window (`wish_window`) and `wen view`

- **Decision: the renderer draws off-screen, the window shows the finished image.** `winit` 0.30 does the window and input, `softbuffer` 0.4 puts the image on the screen (both MIT/Apache-2.0; in the `cargo metadata` scan there is no license outside the allow list, `same-file`/`walkdir` are "Unlicense OR MIT"). Reasons: (1) invariant 6 — wgpu only in `wish_render`; since the surface/presentation is tied to the wgpu instance, the window code would have had to touch the GPU; (2) what is seen in the window is **the same** path as what `wen capture` and the tests see; (3) it also works on software adapters. The cost: a GPU→CPU read every frame (acceptable for a developer viewer); the game runner will build the direct presentation path in M5/M6 (planned work, it does not grow the 1.0 scope). Stable 0.30 was chosen instead of the `winit` 0.31 beta.
- **`wish_window`** (dependencies: `wish_render`, `wish_core`, `winit`, `softbuffer`; knows nothing about scene files): `FlyCamera` (pure arithmetic, unit tested), the `Content` trait (`load`, `name_of`, `fingerprint`), `run(ViewerOptions, &mut dyn Content) -> Report`, `fingerprint_dir` (a fingerprint of file size + change time by extension, polled every 400 ms; `target`, `.git`, hidden folders are skipped).
- **Controls:** right mouse button + mouse looks, W A S D move, Q/E down/up, Shift fast, F the scene's own camera, 1–5 views (lit/ids/depth/normals/wireframe), **left click** names the entity from the id buffer (in the title and in the message), Esc closes. The image is drawn only when it changes (it does not burn CPU when idle).
- **Hot reload was tried in the live window** (software adapter): when a file in the `--shaders` folder changes "shaders reloaded", when the scene file changes "scene reloaded", a broken scene "scene not reloaded, showing the last good one" + a diagnostic with a location; after `--exit-after 4` frames it closed by itself, and the report counted correctly. A load error does not close the window; a scene without a camera gives a message and waits for a change.
- **`wen view --example E --scene S [--root R] [--size WxH] [--view V] [--software] [--shaders D] [--exit-after N] [--json]`.** On this machine a real window was opened, 3 frames were drawn, and it closed.
- **Observation:** the *content* of the window image was not looked at by eye (the window closes quickly, no screenshot was taken); the content comes from the same `render_view` call as `wen capture`, and the only extra step is the RGBA → 0x00RRGGBB conversion. It should be verified by eye in the M3 closing review or at first manual use.
- **The part that cannot be tested in CI (deliberate):** the window loop needs a desktop session; in CI only the pure parts (camera, fingerprint, argument check — `unknown_view` without opening a window) are tested. Running the window path locally with `wen view ... --exit-after 3` is a manual check step.
