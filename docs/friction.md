# Friction log

The M7 method (see [design/M7-showcase-game.md](design/M7-showcase-game.md) §3): every place where we get stuck while making a game with the engine is written here and fixed in the engine, not in the game. The same snag must not happen twice; every fix is protected by a test or an evaluation task.

Types: **tool** (missing tool or parameter), **message** (error message or hint is not enough), **docs** (wrong or missing documentation), **bug**, **API** (gap in the game code SDK), **performance**.

| No | What happened | Type | Cost | Fix | Status |
|---|---|---|---|---|---|

## Release 1.1: the yardstick game (Ridgewatch)

Package 15 of [design/1.1-2d-and-online.md](design/1.1-2d-and-online.md): `examples/ridgewatch`, a hidden-role party game for 4 to 10 players, made with `wen new`, `asset_create`, `tilemap_edit`, `edit_apply`, `wen build`, `wen test` and the `net` tool (design note [design/1.1-ridgewatch.md](design/1.1-ridgewatch.md)).

| No | What happened | Type | Cost | Fix | Status |
|---|---|---|---|---|---|
| F11 | A helper function that took a query (`fn bell_at(bells: &Query<(&Bell, &Transform)>)`) did not compile; rustc spoke of invariance and lifetimes that "do not necessarily outlive" `'static`. The `#[system]` macro gives a system's query references `'static`, which nothing said. | message | 1 build | A compile error about a `Query` and a lifetime gets the engine's own advice first: write `&Query<(&'static Bell, &'static Transform)>` or pass the values (`wish_script::build`, test `a_query_in_a_helper_function_gets_the_engines_advice`) | fixed |
| F12 | With twelve systems the module did not load: "Game code in describe ran out of fuel ... most likely a loop that never ends".
