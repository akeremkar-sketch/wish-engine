# Wish Engine — Working Rules for the Agent Developing the Engine

Wish Engine: an MCP-native, deterministic 3D game engine that is fully integrated with AI but also fully usable without AI (hybrid), open source, and distributed free and without commission. It is written in Rust.

## Invariants (must not be broken)

If a change breaks one of these, the change is wrong. The reasons are in [docs/DECISIONS.md](docs/DECISIONS.md).

1. **Schema first.** A type without a schema cannot enter the world. Every field has a doc comment and, where it fits, a unit and a range.
2. **Determinism.** In simulation code, the wall clock, unseeded randomness, iteration over an unordered collection, and results that depend on thread timing are **forbidden**.
3. **Files are the source of truth.** Canonical format; load → save gives a byte-for-byte identical result.
4. **One control plane.** A new capability is added to `wish_control` first; MCP, the command line and the interface call it. There can be no capability that exists only in the interface.
5. **One diagnostic format.** Every error carries `code`, `message`, a location and a **`hint`**. An error without a written hint counts as unfinished.
6. **Dependencies point down.** Subsystems do not know each other; they talk through the ECS. Outside libraries are used only through their own wrapper crates.
7. **Game code is untrusted.** The Wasm guest must not be able to crash or freeze the engine; no state is kept in the guest.
8. **A feature does not count as done until it is observable/checkable from the control plane and its headless test is written.**
9. **Hybrid parity.** The engine works fully when no AI is connected. Every scene/asset operation the agent can do can also be done by hand from the interface. Manual changes and agent changes enter the same history, with who made them (`actor`).

## Code conventions

- Code, identifiers, API names, diagnostic messages, code comments, commit messages **and all documents in the repository (design notes, ROADMAP, DECISIONS, README, this file)** are in **English** (user decision, 17 November 2026: everything on GitHub is English). The Turkish user guide `docs/user/tr/guide.md` and the editor's `lang/tr.json` are localizations.
- Crate prefix `wish_`; the command-line tool is `wen` (not `wish`: that name is the Tcl/Tk command and would clash).
- License: MIT + Apache-2.0 (open source). Every crate's `Cargo.toml` has `license = "MIT OR Apache-2.0"`.
- `cargo fmt` and warning-free `cargo clippy` are required.
- `unsafe` only in `wish_ecs`, `wish_script` and `wish_sdk` (only at the guest boundary: frame pointer, imports), plus the declaration of the `Plain` contract in `wish_schema` (and the `unsafe impl Plain` the macro generates); every block has a `// SAFETY:` comment explaining why it is safe; tested with Miri. Everywhere else the workspace lint is `unsafe_code = "deny"`.
- No `unwrap`/`expect`/`panic!` in library code (tests excepted); errors are returned as `Diagnostic`. Clippy enforces this (`[workspace.lints]` in `Cargo.toml`).
- Iterating over a `HashMap`/`HashSet` in simulation code is forbidden (clippy `iter_over_hash_type`); if you need ordered iteration, use `BTreeMap` or `Vec`.
- Wherever a stable hash is needed (world hash, fingerprint, anything written to disk), use `wish_core::StableHasher`; never the standard library's hashers.
- Types that enter the world are defined only with `#[component]`, `#[resource]`, `#[event]`, `#[schema]`; `Plain` is never implemented by hand. These macros add `Clone`, `Copy`, `Debug`, `PartialEq`, `Default` and `repr` themselves (writing them again is a compile error).
- Never read a value in `wish_ecs` columns as a whole `&[u8]`: padding bytes may be uninitialized. If you need bytes, copy only the field ranges with `TypeInfo::spans` (`Column::read_into`); to move a value, use a raw copy.
- Components whose consistency the engine itself maintains (currently only `Hierarchy`) are marked `managed` at registration. If you add a new write path, make sure it rejects managed components (`World::check_writable`); the engine's own internal writes use `put_component`.
- Use `wish_core::Result<T>` in functions that return errors. `Diagnostic` is one pointer wide; do not make a change that grows it (a test checks this).
- Put `#![allow(clippy::unwrap_used, clippy::expect_used, clippy::panic)]` at the top of integration test files (`tests/*.rs`): clippy counts only `#[test]` functions as tests, not shared helpers.
- Every public item has a doc comment (these flow into the schema and the MCP docs).
- Coordinate system: right-handed, +Y up, the camera looks toward −Z. Units: meters, seconds, kilograms; radians in the API.
- Before adding a dependency, check its license (only permissive licenses like MIT/Apache-2.0/BSD).

## Verification commands

All three must be clean before every commit (in the project root, PowerShell):

```powershell
$env:Path = "$env:USERPROFILE\.cargo\bin;$env:Path"
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Always give the commit message from a file (`git commit -F <file>`): PowerShell breaks the double quotes in a message given with `-m`, and the commit is left half done.

If you added a dependency, look at its license: the `packages[].license` field in the output of `cargo metadata --format-version 1 | ConvertFrom-Json`; the allowed list is in `deny.toml`.

If you touched a crate that contains `unsafe` (`wish_ecs`, `wish_sdk`), Miri must also be clean (nightly is installed; the first run takes a few minutes, so run it in the background):

```powershell
$env:MIRIFLAGS = '-Zmiri-strict-provenance'
cargo +nightly miri test -p wish_ecs
cargo +nightly miri test -p wish_sdk --test frame
```

The determinism test and the benchmark (`wen bench`) were added in M1; `cargo test --workspace` also runs the compile-fail tests (`trybuild`).
